# Friends of TS Queen Mary — website

Marketing and fundraising site for the [Friends of TS Queen Mary](https://www.tsqueenmary.org.uk),
the registered Scottish charity (SC043623) restoring the last surviving Clyde turbine steamer.

React 19 · Vite 8 · Tailwind CSS v4 · TypeScript. No backend, no database, no
third-party runtime dependencies — the site deploys as static files.

---

## Quick start

**Node 22.12 or newer is required** — Vite 8 refuses to run on anything older,
and the usual symptom is a build that dies with
`You are using Node.js 20.x. Vite requires Node.js version 20.19+ or 22.12+`.
The version is pinned in `.nvmrc`, `.mise.toml` and `package.json` → `engines`.

```bash
nvm use                   # or: mise install
node -v                   # must print v22.12.0 or higher
npm install
cp .env.example .env      # then fill in the private-page values, see below
npm run dev
npm run build             # -> dist/
npm run preview           # serve the built output
npm run typecheck
```

If your editor launches the dev server with a different Node than your shell,
point its task configuration at the correct binary explicitly — `nvm which 22`
prints the path.

## The content pipeline (`tools/`)

Three generators. Their output is committed, so a normal build never needs them —
re-run one only when its input changes.

### `enhance.py` — photographic restoration

```bash
python3 tools/enhance.py          # needs Pillow + numpy
```

Most of the supplied source photographs were small, heavily re-compressed
social-media JPEGs. Each one goes through an edge-preserving chain rather than a
plain resize: chroma denoise, an approximate bilateral filter, percentile auto
levels, progressive 2× Lanczos upscaling with micro-sharpening between steps,
large-radius local contrast, a filmic S-curve, split toning, vibrance, and a
final edge-masked capture sharpen. Monochrome sources skip the colour stages and
get a deeper black point.

It writes a responsive WebP ladder plus one JPEG fallback per image into
`public/img/`, and `src/data/image-manifest.json` with each image's intrinsic
size and a ~20px inline placeholder used for blur-up loading.

Two deliberate limits are encoded in the script:

- Sources at or below 700px wide are never upscaled beyond **2.8×**. Past that,
  Lanczos stops recovering detail and starts inventing texture.
- Those same small sources get **luminance-only** levels plus a constrained
  grey-world white balance. Per-channel levels on a small frame with one
  dominant colour drags the whole white balance with it.

Adding a photograph means adding an entry to the `JOBS` list and a matching
line in the `alt` map in `src/data/images.ts` — the map is exhaustively typed,
so TypeScript will fail the build if you forget.

### `gen_ship.py` — the vector ship

```bash
python3 tools/gen_ship.py out.svg
```

Produces the profile drawing of TS Queen Mary. Every landmark — hull extent,
waterline, deck heights, funnel and mast positions — was measured off the 1933
photograph and is mapped through one scale factor at the top of the file, so the
drawing keeps the ship's real proportions. It was verified by overlaying the
output on the plate at matching scale.

The committed React version is `src/components/brand/ShipProfile.tsx`; it takes
colour props so the same drawing works as a white watermark on the dark hero, a
gold flourish on ivory, and a navy line drawing on white.

### `fetch-fonts.sh` — self-hosted webfonts

```bash
./tools/fetch-fonts.sh
```

Downloads the latin and latin-ext subsets of Inter and Cormorant Garamond and
rewrites `src/fonts.css` to point at local copies. Self-hosting means no visitor
IP address ever reaches a third-party font CDN — which matters for a UK charity
under GDPR — and it lets the CSP forbid outside origins entirely.

## The private collection page

The charity wanted a page that is genuinely hard to find and hard to read
without permission, on a site with no server. There are three independent
layers.

### 1. The URL is not in the source

`routes.tsx` does **not** register the private path. Anything the public routes
do not claim falls through to `src/pages/Unmatched.tsx`, which hashes the
requested path with SHA-256 and compares it, in constant time, against
`VITE_PRIVATE_PATH_HASH`. Only the digest is compiled into the bundle.

Reading the shipped JavaScript therefore tells an attacker that a private page
exists, but not where. A random 16-character path is roughly 96 bits of entropy;
it is not going to be found by guessing or by a crawler.

### 2. The content is encrypted at rest

`content/collection.json` is the plaintext. It is git-ignored and never
deployed. `tools/seal-collection.mjs` encrypts it with AES-256-GCM under a key
derived from the access code via PBKDF2-SHA256 at 600,000 iterations, and writes
the ciphertext to `public/<VITE_PRIVATE_ASSET>.json`.

The page fetches that file only after someone has entered a code, and decrypts
it in the browser with WebCrypto. A wrong code fails at the GCM authentication
tag. Downloading every file the web server will serve yields nothing but random
bytes.

### 3. It is invisible to search engines

No page links to it. It is absent from `sitemap.xml`. It is deliberately **not**
mentioned in `robots.txt` — naming a secret path in a public, routinely-scraped
file is the fastest way to publicise it. The page injects
`noindex, nofollow, noarchive` at runtime, and every host config under `deploy/`
sends `X-Robots-Tag: noindex` on `.json` responses.

Repeated wrong codes are throttled with an exponential backoff held in
`sessionStorage`, which makes online guessing impractical.

### Setting it up

```bash
node tools/private-path.mjs        # prints a fresh path + its hash
```

Put both lines in `.env`, choose an access code, then:

```bash
TSQM_ACCESS_CODE='your-code-here' node tools/seal-collection.mjs
npm run build
```

Rotating the code means re-sealing and redeploying. Note that rotation protects
*future* access: anyone who already downloaded the old ciphertext and knows the
old code can still read that copy.

### What this is not

This is client-side secrecy, not server-side access control. Everyone shares one
code; there is no per-person access, no revocation, and no audit trail, and the
ciphertext is publicly fetchable by anyone who finds the URL. That is the
strongest guarantee available without a backend. If the charity later needs to
know who opened what, or to revoke one person's access, the payload has to move
behind a server that authenticates the request — `src/lib/vault.ts` is small and
self-contained precisely so that swap is easy.

## Security

| Measure | Where |
| --- | --- |
| Content-Security-Policy | `index.html` (meta) **and** every file in `deploy/` |
| HSTS, X-Frame-Options, Referrer-Policy, Permissions-Policy, COOP/CORP | `deploy/` |
| No third-party requests at runtime | self-hosted fonts and images; no analytics |
| No `dangerouslySetInnerHTML` anywhere | — |
| `rel="noopener noreferrer"` on every external link | `Button`, `Footer` |
| Form honeypot + input length caps | `Contact.tsx` |
| Secrets never committed | `.env` and `content/` are git-ignored |

The CSP is strict: `default-src 'self'`, no inline or remote scripts.
`'unsafe-inline'` appears for `style-src` only, because the components use React
inline `style` attributes; it does not permit inline `<script>`.

Two directives are deliberately absent from the `<meta>` CSP and set only as
response headers in `deploy/`:

- **`frame-ancestors`** — browsers ignore it in a meta tag outright.
  Clickjacking is blocked by the `frame-ancestors` and `X-Frame-Options`
  response headers instead.
- **`upgrade-insecure-requests`** — it rewrites every `http://` request to
  `https://`. In production that is the HSTS header's job. In a meta tag it
  *also* applies during development, where the dev server speaks plain http:
  Safari, and any access over a LAN address such as `http://192.168.1.20:5173`,
  then get every request upgraded to a port with no TLS behind it and render a
  blank page. Chrome hides this locally because it exempts `localhost`, so it
  is easy to ship without noticing.

**If you add anything third-party** — Google Analytics, a Stripe or JustGiving
widget, an embedded map or video — it will be blocked until you add its origin
to the CSP in `index.html` *and* the matching file in `deploy/`, and you should
revisit `src/pages/Privacy.tsx`, which currently states that the site sets no
tracking cookies.

## Deployment

This repository builds **two independent websites** from one source tree.

| Build | What it is | Published to |
| --- | --- | --- |
| `npm run build:public` | the charity's seven public pages | `rajkumar-code29/tsqm` → https://rajkumar-code29.github.io/tsqm/ |
| `npm run build:collection` | the gated Fabergé collection | `rajkumar-code29/tsqm-collection` → https://rajkumar-code29.github.io/tsqm-collection/ |

They are separate builds rather than one build with a hidden corner, and the
split is enforced by the entry points: `index.html` → `src/main.tsx` →
`routes.tsx` never imports the collection, so the public bundle provably
cannot contain it. `collection.html` → `src/main-collection.tsx` →
`routes-collection.tsx` carries only the gate and the sealed payload, and none
of the public pages.

On the collection deployment every path is a dead end except the one whose
SHA-256 matches `VITE_PRIVATE_PATH_HASH` — including its own root, so finding
the deployment tells a visitor nothing.

### Publishing

```bash
./tools/deploy.sh build       # build both, publish neither
./tools/deploy.sh             # build and publish both
./tools/deploy.sh public      # just the charity site
./tools/deploy.sh collection  # just the collection
```

Each site is force-pushed to the `gh-pages` branch of its own repository.
That branch is a publish target, not history — `main` is the source of truth.

The script also does the three things GitHub Pages needs and Vite does not do:

- copies `index.html` to **`404.html`**, because Pages has no rewrite rules and
  a client-side router otherwise 404s on every deep link and on the private URL
- writes **`.nojekyll`**, without which Pages runs the output through Jekyll and
  silently drops files whose names begin with an underscore
- **strips the sealed payload from the public build** and prunes the charity's
  photography from the collection build, so neither site carries the other's files

### GitHub Pages caveats

Pages serves no custom response headers, so `deploy/_headers` and the other
host configs do **not** apply there. The CSP in the HTML `<meta>` still does;
`frame-ancestors`, `X-Frame-Options` and HSTS do not. `github.io` is
HSTS-preloaded by Google, which covers transport, but if the charity wants the
full header set the site should go to Netlify — `deploy/netlify.toml` is still
in the repository and still correct.

### Other hosts

| Host | Use | Notes |
| --- | --- | --- |
| Netlify / Cloudflare Pages | `deploy/netlify.toml` | `public/_headers` is already copied into the build |
| Vercel | `deploy/vercel.json` | copy to the project root |
| Apache / cPanel | `deploy/.htaccess` | upload alongside `index.html` |
| nginx | `deploy/nginx.conf` | merge into your server block |

On any of these, set `PUBLIC_BASE=/` (and `COLLECTION_BASE=/`) — the `/tsqm/`
default exists only because Pages serves a project site from a subdirectory.

### Before going live

- [ ] Point the contact form at a real endpoint — `Contact.tsx` currently
      resolves a stubbed promise and never sends anything
- [ ] Wire the Donate buttons to the charity's payment provider (they link to
      `/support` today)
- [ ] Replace the placeholder plates on the private page with real photography
- [ ] Have the trustees check the historical copy in `src/data/content.ts`. It is
      drawn from public sources and the charity's own Facebook posts, and has not
      been verified against their archive.
- [ ] Decide whether the collection should live on a public host at all. The
      repository is public, so its ciphertext is downloadable by anyone and can
      be attacked offline at leisure. The access code is the only thing
      protecting it — keep it long, and rotate it with `npm run seal` if it is
      ever shared carelessly.

## Accessibility

Semantic landmarks and heading order, a skip link, visible focus rings, labelled
form fields, `aria-live` on async status messages, an `inert` mobile drawer while
closed, and alt text for every photograph (centralised in `src/data/images.ts`).
All motion — scroll reveals, hover zooms, the smooth scroll — is disabled under
`prefers-reduced-motion`. The before/after slider is a real range input, so it
works with a keyboard and is announced correctly.
